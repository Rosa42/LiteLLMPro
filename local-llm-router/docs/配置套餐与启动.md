# 配置新套餐 + 启动指南（Windows）

## 1. 核心概念

| 概念 | 含义 |
|------|------|
| **套餐 / quota_group** | 同一 API Key、同一额度池。熔断按套餐，不是按模型 |
| **model_name** | 客户端请求的模型名（如 `glm-5.2`） |
| **priority** | 数字**越小**越优先填满（Fill First） |
| **upstream_protocol** | 部署实际上游协议（如 `openai_chat`）。**不会**自动开放公网端点 |
| **public_protocols** | 逻辑模型公网协议 opt-in（写在 `logical_models`） |
| **上游 Key** | 只写在 `.env`，不进 Git |
| **中转 Key** | `.env` 的 `LITELLM_MASTER_KEY`，给 OpenCode/客户端用 |

协议相关开发进度见 `docs/tasks.md` §0（M1 已完成；M2 路由过滤未做）。

协议发现（M1-05）：

```text
GET http://127.0.0.1:4000/v1/router/model-capabilities
Authorization: Bearer <LITELLM_MASTER_KEY>
```

注意：标准 `GET /v1/models` **不含** `public_protocols`（LiteLLM v1.90.5 限制）。
同一 `model_name` 可以出现在多个套餐下 → 组成**模型组**，由路由按 priority + 额度状态选账号。

## 2. 推荐流程（脚本）

在项目根目录 `local-llm-router`：

```powershell
cd E:\LiteLLMPro\local-llm-router

# 首次
.\scripts\llm-router.ps1 init

# 添加/更新一个套餐（写 .env + plans.yaml，并生成 litellm.yaml）
.\scripts\llm-router.ps1 add-plan `
  -Id volc-c `
  -BaseUrl "https://ark.cn-beijing.volces.com/api/coding/v3" `
  -ApiKey "ark-你的密钥" `
  -Models "glm-5.2,ark-code-latest,glm-latest" `
  -Priority 10

# 启动
.\scripts\llm-router.ps1 start

# 状态 / 冒烟
.\scripts\llm-router.ps1 status
.\scripts\llm-router.ps1 smoke -Model glm-5.2

# 视觉门面：列出槽位 / 切换执行模型（详见 §7）
.\scripts\llm-router.ps1 compose-vision-slots
```

第二套餐（额度独立，耗尽后可切）：

```powershell
.\scripts\llm-router.ps1 add-plan `
  -Id volc-d `
  -BaseUrl "https://ark.cn-beijing.volces.com/api/coding/v3" `
  -ApiKey "ark-第二把Key" `
  -Models "glm-5.2,ark-code-latest" `
  -Priority 20

.\scripts\llm-router.ps1 restart
```

## 3. 手动配置（不用 add-plan）

### 3.1 `.env` 增加密钥

```env
VOLC_CODING_BASE_URL=https://ark.cn-beijing.volces.com/api/coding/v3
VOLC_CODING_KEY_C=ark-xxx

# 视觉译图（门面需要）
MINIMAX_ANTHROPIC_BASE_URL=https://api.minimaxi.com/anthropic
MINIMAX_API_KEY=

# 视觉门面（默认关；现网译图须两个都 true）
# GATEWAY_ENHANCE_ENABLED=true
# VISION_COMPOSE_ENABLED=true

# 第二套餐
PLAN_VOLC_D_BASE_URL=https://ark.cn-beijing.volces.com/api/coding/v3
PLAN_VOLC_D_API_KEY=ark-yyy
```

常见 Base URL：

| 套餐类型 | OpenAI 兼容 Base |
|----------|------------------|
| 火山 Coding Plan | `https://ark.cn-beijing.volces.com/api/coding/v3` |
| 火山 Agent Plan | `https://ark.cn-beijing.volces.com/api/plan/v3` |
| 其它 OpenAI 兼容 | 供应商文档中的 `/v1` 根 |

**不要**把 Coding Plan 配成普通 `.../api/v3`（会按量计费、不走套餐额度）。

### 3.2 `config/plans.yaml`

```yaml
plans:
  - id: volc-c
    display_name: Volc C
    provider_id: volcengine
    priority: 10
    base_url_env: VOLC_CODING_BASE_URL
    api_key_env: VOLC_CODING_KEY_C
    models:
      - glm-5.2
      - ark-code-latest
```

**只写套餐真实支持的模型。** 例如当前 Coding Plan 若不支持 `kimi-k3`，不要写进去（会 404 UnsupportedModel）。

### 3.3 生成并启动

```powershell
.\scripts\llm-router.ps1 apply
.\scripts\llm-router.ps1 restart
```

`apply` 会用 `plans.yaml` **覆盖** `config/litellm.yaml` 的 `model_list`。

## 4. 启动 / 停止

| 命令 | 作用 |
|------|------|
| `.\scripts\llm-router.ps1 start` | 起 Redis + LiteLLM |
| `.\scripts\llm-router.ps1 stop` | 停 LiteLLM（默认不停 Redis） |
| `.\scripts\llm-router.ps1 restart` | 重启 |
| `.\scripts\llm-router.ps1 status` | 健康检查 + 模型列表 |
| `.\scripts\llm-router.ps1 compose-vision-slots` | 列出 execute / 译图候选 |
| `.\scripts\llm-router.ps1 compose-vision-update` | 切换门面槽位（预置 id 要 `-Force`） |

客户端：

| 项 | 值 |
|----|-----|
| API Base | `http://127.0.0.1:4000/v1` |
| API Key | `.env` 的 `LITELLM_MASTER_KEY` |
| Model | 如 `glm-5.2` / `glm-5.2-vision`（OpenCode 写 `local-litellm-anthropic/glm-5.2-vision`） |

日志：`.tools/litellm-local.err.log`

### Docker（可选）

```powershell
docker compose --env-file .env -f deploy/docker-compose.yaml --profile core up -d --build
```

本机 Docker 不稳时用 `llm-router.ps1 start` 即可。

## 6. 排错

| 现象 | 原因 |
|------|------|
| `UnsupportedModel` / coding plan feature | 该模型不在当前套餐可用列表 → 改 models |
| `JSON parsing failed: Text: 你好` | 旧版流式 hook bug；请用当前代码并 restart |
| 401 | 客户端没用 `LITELLM_MASTER_KEY` |
| Redis / fail-closed | Redis 未起；再执行 `start` |
| 改了配置不生效 | 需 `apply` + `restart` |
| 视觉门面带图 400 / discovery 没有门面 | 检查 `.env` 是否同时开了 `GATEWAY_ENHANCE_ENABLED` 与 `VISION_COMPOSE_ENABLED`；项目能力列表才省略门面，stock `/v1/models` 不会 |

## 7. 视觉门面（使用）

预置逻辑名仍是 `glm-5.2-vision`。V1 只服务 **Anthropic Messages**（带图走 `/v1/messages`）。执行模型 / 译图模型可在宿主机切换，**不要**在 Docker 容器里改 `plans.yaml`。

使用说明全文：[`USAGE.md`](../USAGE.md) §4。纪律与回滚：[`docs/framework-upgrade/maintenance.md`](../../docs/framework-upgrade/maintenance.md)。

`.env` 须同时：

```env
GATEWAY_ENHANCE_ENABLED=true
VISION_COMPOSE_ENABLED=true
```

```powershell
.\scripts\llm-router.ps1 compose-vision-slots
.\scripts\llm-router.ps1 compose-vision-update `
  -Id glm-5.2-vision -Execute glm-5.3 -Vision MiniMax-M3 -Force
.\scripts\llm-router.ps1 compose-vision-add `
  -Id my-vision -Execute glm-5.3 -Vision MiniMax-M3
.\scripts\llm-router.ps1 compose-vision-remove -Id my-vision
```

apply 后核对 `config/litellm.yaml`：上游是 `anthropic/<execute_model>`，凭证跟 execute 的 Volc plan，不是 MiniMax。只改 yaml 则 `restart`；改了 `plugins/` 才需要 Docker `--build`。

库存执行槽位是 `glm-5.3`（没有单独的 `glm-5.3-flash`）。译图候选必须 Messages + IMAGE（`MiniMax-M3` 可以，`MiniMax-M2.7` 不可以）。无图不调译图。译图失败 400，不会换执行模型。

`remove` 不得指向 `glm-5.2` / `MiniMax-M3` 等非门面逻辑名。stock `/v1/models` 不会因关 flag 而丢掉门面行。
