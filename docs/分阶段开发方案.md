## 0. 文档目的与使用方式

本文档将总设计方案拆为可执行阶段，供本地 AGENT / 人工按序落地。

| 用途 | 说明 |
|------|------|
| 执行顺序 | 严格按阶段依赖推进；未完成验收不得进入下一阶段 |
| 交付物 | 每阶段列出「代码 / 配置 / 测试 / 文档」产出 |
| 验收门禁 | 每阶段必须有可勾选、**可测**的完成标准 |
| 风险记录 | 已知风险与规避策略写入本阶段，不跨阶段静默假设 |

### 0.1 强制约束（全文适用）

1. 不直接修改 LiteLLM 业务核心；业务逻辑仅在 `plugins/shared_quota_router/`（运行时包名 **`shared_quota_router`**）。
2. 优先 Custom Routing Strategy + CustomLogger；必要时仅允许最小注册补丁（**补丁内无业务逻辑**）。
3. 禁止写入 / 提交真实 Secret；禁止自动 `git push`（除非用户显式授权）。
4. **禁止**把所有 429 当作套餐耗尽；**禁止**流式首字节后拼接另一上游。
5. 不得跳过测试；不得关闭类型检查来“通过”构建。
6. Redis 不可用时 **fail-closed**：不得静默把未知状态当作 AVAILABLE，不得盲选全部 deployment。
7. **模型组 ≠ 额度组**：过滤与熔断必须按 `quota_group_id`；A/kimi 耗尽 → A 下全部模型不可用。
8. **禁止默认跨模型降级**（无用户明确允许时不得配置 Kimi→GLM fallback）。
9. **被动额度 only**（阶段 1–15 主线）：不做 `quota_collectors`、Cookie 登录、未公开余额页、预测剩余额度。
10. **M2a 不宣称** 总设计 §23 系统交付清单全部勾选。

### 0.2 测试策略总则

```text
阶段 N 结束 = 该阶段列出的单测（及适用的 C0/C1 契约）全绿
禁止：等到阶段 11 才第一次跑扩展点契约
阶段 11 = §17.1 补全 + §17.2 全矩阵 + 升级门禁
```

| 契约包 | 阶段 | 内容 |
|--------|------|------|
| **C0** | 7 门禁 | `CustomRoutingStrategyBase` 可导入；策略可挂到 Router；`model_info` 自定义字段在选路路径可读 |
| **C1** | 8 门禁 | failure callback 触发且可解析 `deployment_id` / `quota_group_id`；失败后下次选路避开已熔断 group |
| **全量** | 11 | 总设计 §17.2 完整矩阵 |

### 0.3 跨阶段接口契约（开工阻断项）

#### 包与加载

| 项 | 约定 |
|----|------|
| 源码路径 | `plugins/shared_quota_router/` |
| 镜像路径 | `/app/shared_quota_router` |
| import 名 | `shared_quota_router` |
| PYTHONPATH | 含 `/app` |
| 回调单例 | `shared_quota_router.callback_instance`（阶段 8 交付） |
| 注册入口 | `shared_quota_router.bootstrap.register()` 为唯一官方注册入口 |
| 最小 patch | 仅注册策略对象；构建时 apply；`patches/README.md` 说明如何验证「无业务逻辑」 |

#### RequestRoutingContext（阶段 5 定义类型，7/8 使用）

```text
request_id: str
tried_quota_groups: set[str]
first_byte_sent: bool
max_quota_groups: int = 3
```

- 同请求内：同一 `quota_group` 最多尝试 1 次；不同 group 最多 3 次。
- `first_byte_sent=True` → **禁止**跨 deployment 重试 / 切换。

#### StateStore 最小 API + fail-closed

```text
get_provider / get_quota_group / get_deployment
mark_exhausted / set_status（revision 乐观锁）
lease acquire/release + inflight
```

- Redis DOWN 或 get 超时 → 策略层 **不得**选出依赖未知状态的 deployment；请求失败可观测；**禁止**静默降级为「全部 AVAILABLE」或回退盲选。

#### Recovery Worker

```text
probe_target = registry.pick_probe_deployment(quota_group_id)
# 组内任意 enabled deployment；model_group 优先级可配置
凭证：与 litellm.yaml litellm_params 同源（环境变量映射）
探针：直连上游，不经用户 Router，不触发 fallback
probe-lock TTL；PROBING 超时 → 回 EXHAUSTED + next_probe_at
```

## 9. 阶段 8：实现失败回调（+C1 + 流式硬开关）

### 9.1 目标

失败分类 → 更新状态 → 清 affinity → 与重试语义对齐；**first_byte_sent 硬禁止再切**。

### 9.2 工作内容

1. `callbacks.py`：success / failure；释放 lease；更新 last_success
2. 按 `FailureKind`：
   - SHARED_QUOTA_EXHAUSTED → 整组 EXHAUSTED + 清该账号 affinity
   - SHORT_RATE_LIMIT → 仅 deployment cooldown
   - AUTH_INVALID → DISABLED + 告警钩子
3. 写入 / 读取 `RequestRoutingContext`：tried、是否允许 retry、`first_byte_sent`
4. **Blocking 单测**：`first_byte_sent=True` 时不得发起跨 deployment 重试
5. 请求级：≤3 group / 同 group 1 次（与策略协同）
6. **联合验收句**：A/kimi 高置信耗尽 → A/glm 亦不可选
7. `metrics.py` 指标名骨架；日志脱敏
8. 交付 `callback_instance` 与 yaml 引用一致
9. **C1 契约测试**

### 9.3 验收标准

- [ ] 耗尽 → 整组 EXHAUSTED + 清 affinity
- [ ] 短 429 → 仅 deployment；QuotaGroup 仍 AVAILABLE
- [ ] 鉴权 → DISABLED
- [ ] **first_byte_sent 禁止再切（单测）**
- [ ] 同请求切换上限行为可测
- [ ] A 组跨模型同时熔断联合断言通过
- [ ] 成功路径释放 lease
- [ ] 指标/日志无 Key、完整 prompt、Authorization
- [ ] **C1 全绿**
- [ ] `callback_instance` 可被配置加载

### 9.4 预估

约 1.5–2 人日。

### 9.5 说明

阶段 13 保留 SSE 注入与指标专项，**不**承担「第一次实现 first_byte 开关」职责。

## 10. 阶段 9：实现恢复 Worker（→ M2a）

### 10.1 目标

EXHAUSTED 到期探测 → PROBING → AVAILABLE 或退避；完成 M2a。

### 10.2 工作内容

1. `recovery_worker.py`：扫描、锁、探针、退避（5m/15m/30m/60m，上限参考 2h）
2. `reset_at` 优先于盲目退避
